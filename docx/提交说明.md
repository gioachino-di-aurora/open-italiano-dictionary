# Open Italiano Dictionary 词典数据格式

## 1. 提交前必须阅读官方词典

在提交任何新的词典数据之前，必须首先阅读项目中的官方词典文件：

`dictionary/词.md`

`词.md` 是本项目词典数据格式的官方范例。

贡献者必须按照 `词.md` 中已经存在的词条格式提交新内容。

**不要自行设计新的字段、标题结构或数据格式。**

如果无法确定某项内容应该如何填写，应当首先在 `词.md` 中查找相同类型的词条作为参考。

---

## 2. 官方目录标题

词典中的目录标题必须与官方版本完全保持一致。

标题的：

- 文字
- 拼写
- 标点
- 层级

均不得自行修改。

词典内容的顺序可以调整，但目录标题本身必须与官方版本一致。

如果认为目录标题需要修改，应提交 Issue，由维护者统一处理。

---

## 3. 词条类型

本项目目前主要收录：

- 名词
- 动词
- 形容词
- 副词
- 介词
- 其他按照官方词典标准收录的词类

词条的词性必须使用官方规定的缩写。

例如：

```text
s.m.
s.f.
v.tr.
v.intr.
agg.
avv.
prep.
```

**不得因为中文名称而自行判断词性。**

例如：

```text
pronto
```

官方词性为：

```text
agg.
```

因此应按照形容词处理，而不是因为某些使用场景而将其标记为副词。

---

## 4. 名词格式

名词按照官方词典的格式记录。

例如：

```text
inizio

* pos: s.m.
* definitions_zh: 开始；开端；起点；开头；初期
* inflection: 单数 inizio；复数 inizi；冠词 l’inizio
* auxiliary: null
* compound_tenses: null
* memory_items: 阳性；复数 inizi。
```

另一个例子：

```text
lavoro

* pos: s.m.
* definitions_zh: 工作；劳动；工作岗位；职业；职务；工作任务；工作成果；作品；作业
* inflection: 复数 lavori
* auxiliary: null
* compound_tenses: null
* memory_items: 阳性；复数 lavori。
```

名词的词形信息应记录在 `inflection` 中。

没有助动词和复合时态的名词，应按照官方格式使用：

```text
* auxiliary: null
* compound_tenses: null
```

---

## 5. 形容词格式

形容词使用：

```text
* pos: agg.
```

例如：

```text
pronto

* pos: agg.
* definitions_zh: 准备好的；准备就绪的；现成的；迅速的；立即用的；敏捷的；机警的；成熟的
* inflection: pronto / pronta / pronti / pronte
* auxiliary: null
* compound_tenses: null
* memory_items: 也可作 inter.：喂；您好。
```

形容词的阴阳性和单复数形式按照官方词典的表示方法填写。

如果一个形容词还具有其他词类用法，应按照官方词典的规定记录。

---

## 6. 副词格式

副词使用：

```text
* pos: avv.
```

副词不得因为其中文含义或句法位置而错误标记为 `agg.`。

具体格式必须参考 `词.md` 中已经存在的官方副词词条。

---

## 7. 介词格式

介词使用：

```text
* pos: prep.
```

例如：

```text
per

* pos: prep.
* definitions_zh: 为了；对于；给；向；到；经过；通过；由；每；以；在……方面
* inflection: null
* auxiliary: null
* compound_tenses: null
* memory_items: 介词，无变位。
```

没有词形变化的词，应使用：

```text
null
```

---

## 8. 动词格式

动词必须使用：

```text
* pos: v.tr.
```

或：

```text
* pos: v.intr.
```

等官方规定的动词词性。

动词的 `inflection` 可以包含多个时态和语法形式。

例如 `dare`：

```text
dare

v.tr.

definitions_zh
  * 给；给予；交给；送给；提供；发给；带来；造成；产生；给予某人某物；举办；进行；支付；发出；提供帮助

inflection
  * 现在时：
      + io: do
      + tu: dai
      + lui/lei: dà
      + noi: diamo
      + voi: date
      + loro: danno
  * 过去分词（p.pass.）：dato
  * 现在分词（p.pres.）：dante
  * 现在副动词（ger. pres.）：dando
  * 过去副动词（ger. pass.）：avendo dato
  * 将来时：
      + io: darò
      + tu: darai
      + lui/lei: darà
      + noi: daremo
      + voi: darete
      + loro: daranno
  * 条件式：
      + io: darei
      + tu: daresti
      + lui/lei: darebbe
      + noi: daremmo
      + voi: dareste
      + loro: darebbero
  * 虚拟现在时：
      + che io: dia
      + che tu: dia
      + che lui/lei: dia
      + che noi: diamo
      + che voi: diate
      + che loro: diano
  * 命令式：
      + tu: da’/dai!
      + Lei: dia!
      + noi: diamo!
      + voi: date!
      + Loro: diano!

auxiliary
  * aus.：avere

compound_tenses
  * 模板：avere + dato
  * passato prossimo：
      + io: ho dato
      + tu: hai dato
      + lui/lei: ha dato
      + noi: abbiamo dato
      + voi: avete dato
      + loro: hanno dato
```

动词的具体时态、语式和排列方式必须以官方 `词.md` 为准。

不得因为其他意大利语教材采用不同的排列方式而自行改变本项目格式。

---

## 9. 自动词形与特殊词形

并非所有词的词形都可以简单按照普通规则推导。

以下词形属于项目规定的**必须单独记忆词形**：

```text
notizia → notizie
agenzia → agenzie
pronuncia → pronunce
città → 单复数同形
personalità → 单复数同形
```

这些内容应当保存在项目规定的特殊词形总表中。

自动生成工具不得仅根据普通规则覆盖这些人工确认的特殊词形。

---

## 10. 字段

正式词条使用项目规定的字段。

目前官方词条中使用的主要字段包括：

```text
pos
definitions_zh
inflection
auxiliary
compound_tenses
memory_items
```

不同词类可以根据官方词典的实际结构具有不同内容。

字段名称不得自行修改。

例如：

```text
definitions_zh
```

不得自行改成：

```text
meaning
translation
chinese
```

---

## 11. 空值

没有对应数据的字段按照官方词典使用：

```text
null
```

例如：

```text
* inflection: null
* auxiliary: null
* compound_tenses: null
```

不要自行使用：

```text
无
没有
N/A
none
-
```

等其他形式。

---

## 12. 数据顺序

词条在词典中的排列顺序可以调整。

但是：

**目录标题必须与官方版本完全一致。**

字段和内容的具体组织方式必须遵守官方词典格式。

如果官方格式对某一类词条规定了特定的结构，应当按照该结构提交。

---

## 13. 外来语

外来语必须遵守：

`docs/FOREIGN_WORDS.md`

中的规定。

外来语必须明确声明其外来语性质。

如果检测确认投稿内容属于外来语，但投稿者没有声明：

**直接拒绝。**

不得将未声明的外来语作为普通意大利语词条提交。

---

## 14. 提交新词条

提交新词条前，必须：

1. 阅读 `dictionary/词.md`。
2. 查找与准备提交的词条类型相同或相近的官方词条。
3. 按照官方格式填写。
4. 确认词性。
5. 确认中文释义。
6. 确认词形。
7. 检查是否属于外来语。
8. 如果属于外来语，按照外来语规范进行声明。
9. 检查是否已经存在相同词条。
10. 确认没有明显的数据错误。

只有符合官方词典格式的数据才可以提交。

---

## 15. 发现词典数据错误

如果发现官方词典中的任何数据存在错误：

**不要直接修改正式词典数据。**

请提交 GitHub Issue。

Issue 中应尽可能说明：

- 词条名称
- 错误内容
- 错误位置
- 当前数据
- 建议修改内容
- 错误原因
- 可靠来源

维护者会审核 Issue，并决定是否修改正式词典。

---

## 16. AI 审核

项目可以使用 AI 辅助检查提交的数据。

AI 可以检查：

- 意大利语拼写
- 中文释义
- 词性
- 词形
- 动词变位
- 助动词
- 复合时态
- 重复词条
- 非意大利语内容
- 外来语声明
- Markdown 格式

AI 发现问题后，只能提出审核意见。

AI 不得未经人工审核直接修改正式词典。

发现问题的数据应被标记，并进入人工审核流程。

---

## 17. 格式修改

如果贡献者认为现有词典格式存在问题：

**不要直接在提交的新词条中使用新的格式。**

请提交 Issue，说明：

- 当前格式
- 存在的问题
- 建议的新格式
- 使用新格式的必要性

只有维护者确认后，才能修改官方数据格式。

---

## 18. 最重要的规则

### 新增内容

先阅读：

`dictionary/词.md`

然后严格按照官方词典已有格式提交。

### 发现错误

提交：

**GitHub Issue**

不要直接修改正式词典数据。

### 外来语

必须声明。

未声明：

**直接拒绝。**

### 格式

目录标题必须与官方版本完全一致。

内容顺序可以调整。

### 工具

工具可以自由替换。

Python、JavaScript、Rust、Go 或其他语言都可以重新实现工具。

但是：

**正式词典数据必须遵守本项目的数据格式。**
